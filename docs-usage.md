# ecosystem-gap-audit — как пользоваться

Практическое руководство: что запускать, в каком порядке, как читать вывод и чего не делать.
Метод и его ограничения — в SKILL.md, здесь — работа руками.

## Зачем

Ответ на вопрос «что создать, чего ещё нет» — с цифрами, а не по ощущению. На выходе
не список идей, а план с проверенными фактами: какие ниши пусты, какие заняты заглушками,
у каких конкурентов нулевой adoption и где именно остаётся незанятая часть.

Хорошо работает перед выбором продукта, перед публикацией пакета, при аудите зависимостей,
при мониторинге конкурентов.

## Что нужно

- Python 3.8+ и только стандартная библиотека — ставить нечего.
- Авторизованный `gh` (`gh auth status`) — даёт 5000 запросов/час вместо 60. Без него
  работает только `check_predecessors.py` (он ходит в npm/PyPI напрямую).
- Сеть. `jq` не нужен: парсинг идёт в Python.
- Windows/MSYS: запускай через `python`, пути к скриптам давай в нативном виде
  (`C:/Users/...`), рабочие данные клади рядом с отчётом, а не в `TMPDIR` (чистится через сутки).

## Состав


## Быстрый старт (минимальный путь)

Если нужно ответить «занята ли ниша X» за пять минут — хватит одной команды:

```bash
python scripts/check_predecessors.py gerenuk redherring ci-triage
```

Колонка `MCP` покажет, есть ли у пакета агентский интерфейс; колонка `вердикт` — жив ли он.
Клетка «ЖИВО + MCP нет» — это и есть незанятая часть ниши.

## Шаг 1. collect.py — собрать каталог экосистемы

Правишь `CONFIG` в начале файла (ключевое слово экосистемы, URL каталога, темы GitHub,
порог звёзд) и запускаешь:

```bash
mkdir -p raw && python collect.py
```

Создаёт в `raw/`: `catalog.json` (каталог целиком), `ecosystem_repos.json` (репозитории
самой экосистемы), `popular.json` (популярные репозитории по темам).

Правило, нарушение которого дорого стоит: **каталог пагинируется до конца**, а курсор
читается по реальному имени ключа. В разборе ключ был в camelCase (`nextCursor`), скрипт
читал `next_cursor`, молча останавливался на первой странице — и в отчёт ушло «8000», тогда
как реально их 158 062. Проверяй в логе строку о конце курсора, а не только число записей.

Живой признак неполноты: если в 100 записях страницы меньше 100 уникальных имён — каталог
хранит версии, и число имён всегда меньше числа записей, но оно не должно падать втрое
на первой странице.

## Шаг 2. coverage.py — карта плотности и список кандидатов

```bash
python coverage.py
```

Два вывода, оба обязательны:
- **плотность классов задач** — сколько записей каталога упоминают каждый класс. Сразу видно
  перегретые классы (не лезть) и пустые (возможность);
- **список кандидатов** — популярные инструменты, для которых в каталоге не нашлось
  упоминания экосистемы, отсортированные по звёздам и отфильтрованные от awesome-списков,
  курсов и учебных подборок.

Смотри в файле списки `GENERIC`, `BAD_NAME`, `BAD_DESC`, `BAD_LANG` и корректируй под свою
экосистему: без них в топ выдачи попадают «30 дней до», подборки и книги.

Важно: **доли считай только на полном каталоге**. В разборе вывод «локально ставимых 16.5%,
это недокормленный сегмент» держался на срезе в 6% и после полного обхода развернулся на
52.9% — то есть на противоположный.

## Шаг 3. verify.py — проверить инструмент по GitHub

```bash
python verify.py owner/repo owner2/repo2        # или список из gap_tools.json
```

Вердикты: `НЕТ` / `ЗАГЛУШКА` / `СЛАБЫЙ` / `ЖИВОЙ`. Порог заглушки: меньше 25★ или push
старше 365 дней. Рядом со вердиктом всегда печатается сама находка — читай её глазами.

Для имён короче пяти букв и для родовых слов («uv», «ruff», «core») выдача шумная: на «ruff»
лучшим совпадением выходил анализатор на 11★, на «uv» — чужой docker-плагин. Вердикт в такой
строке без чтения находки ничего не значит.

Два режима, которые часто нужнее основного:

```bash
# другой класс артефакта вместо MCP
python verify.py --keyword "helm chart" traefik/traefik grafana/grafana
python verify.py --keyword "vscode extension" astral-sh/ruff
python verify.py --keyword "terraform provider" hashicorp/terraform
```

По умолчанию скрипт дополнительно смотрит репозитории организации вендора и помечает находку
«org». Это не мелочь: у крупных проектов репозиторий часто назван по назначению, а не по
продукту, и поиск по имени продукта его теряет. Так находятся `grafana/mcp-grafana` (3571★),
`traefik/traefik-helm-chart` (1419★) и `Dokploy/mcp` (401★) — все три поиск по имени пропускал.

## Шаг 4. check_predecessors.py — предшественники и adoption

Главный скрипт при выборе ниши. Шесть режимов:

```bash
# 1) таблица: версия, дата, скачивания, MCP-поверхность, вердикт
python check_predecessors.py gerenuk redherring ci-triage

# 2) свободно ли имя перед публикацией
python check_predecessors.py --check-name tests-for-diff
#   СВОБОДНО    tests-for-diff — нет ни в PyPI, ни в npm
#   ЗАНЯТО      requests — pypi, 2.34.2, 2026-05-14, 317314822 скач/нед

# 3) аудит зависимостей проекта
python check_predecessors.py --from requirements.txt --csv deps.csv

# 4) мониторинг: что изменилось с прошлого прогона
python check_predecessors.py --from requirements.txt --diff raw/predecessors.json

# 5) типосквоттинг: похожие имена (Левенштейн ≤ 2)
python check_predecessors.py --similar reqeusts     # → d=2  requests

# 6) гейт для cron/CI: код выхода 2, если есть живые или MCP=да
python check_predecessors.py --from requirements.txt --strict
```

### Как читать вердикты

| Вердикт | Порог | Что значит |
|---|---|---|
| `ОТСУТСТВУЕТ` | нет ни в PyPI, ни в npm | ниши нет: ни одной реализации |
| `МЁРТВО` | < 10 скач/нед или < 40/мес | опубликовано и не принято |
| `СЛАБО` | 10–99/нед или 40–399/мес | кто-то пользуется, но рынка нет |
| `ЖИВО` | ≥ 100/нед или ≥ 400/мес | настоящий конкурент |
| `ЗАСТОЙ` | adoption высокий, но релиза нет > 540 дней | зависимость-зомби: скачивают, не развивают (nose: 6 млн/мес при релизе 2015 года) |
| `ЕСТЬ (adoption не измерен)` | — | странный случай, проверить руками |

Пороги — это `ALIVE_WEEKLY`, `ALIVE_MONTHLY`, `DEAD_WEEKLY`, `DEAD_MONTHLY` в начале скрипта.
Для узких профессиональных инструментов 100 скач/нед слишком много: опускай `ALIVE_WEEKLY`
до 20–30, иначе всё выглядит мёртвым. Порог застоя — `STALE_DAYS` (по умолчанию 540 дней).

Колонка `MCP` — это наличие агентского интерфейса **внутри самого пакета** (по описанию и
README), а не в экосистеме. «MCP: нет» у ruff, uv, mypy означает «вендор ещё не встроил», а не
«сторонних серверов не существует» — вторую половину доказывает `verify.py`.

## Шаг 5. catalog_build.py — собрать каталог по описанию

Когда области ещё нет каталога, его собирают из поиска по фразе. Скрипт опрашивает три
источника, склеивает дубли и строит каталог с метриками.

```bash
python catalog_build.py "test impact analysis" --extra "flaky test detection" \
       --pages 1 --min-stars 20 --md catalog.md
```

Источники и их свойства:

| Источник | Что даёт | Ограничение |
|---|---|---|
| GitHub (`in:description,readme`) | звёзды, язык, дата push, теги | Search API — 30 запросов/мин |
| npm (`-/v1/search`) | пакеты, даты, ключевые слова | возвращает много рыхлых совпадений |
| Реестр MCP (`search=`) | серверы | матчит узко, часто 0 результатов |
| PyPI | — | **публичного поиска по описанию нет** |

Что скрипт делает с сырой выдачей (без этого каталог бесполезен):

1. **Ищет фразу в кавычках** — иначе «test impact analysis» тянет проекты, где эти слова
   встречаются по отдельности;
2. **снимает дубли между источниками** — один проект на GitHub и в npm становится одной
   записью с пометкой `sources`, а не двумя;
3. **фильтрует шум** — awesome-подборки, курсы, учебные репозитории (в первом прогоне на
   620 проектов верх занимали awesome-списки на 520 тыс. звёзд);
4. **проверяет релевантность** — значимое слово фразы должно быть в имени или описании;
5. **считает метрики**: источники, языки, долю живых (push ≤ 90 дней), заброшенных,
   частые теги, топ по звёздам.

Ключи: `--merge FILE` (долить к собранному ранее каталогу), `--out` (JSON), `--md` (таблица
markdown для чтения), `--no-npm`, `--no-registry`.

Практический итог прогона по тестовому триажу: 268 проектов, из них push за 90 дней у 149,
заброшенных 80; в топе — `guidewire-oss/fern-platform` (456★), `ctrf-io/github-test-reporter`
(378★), `rpau/junit4git` (47★, «JUnit Extensions for Test Impact Analysis»). Ни одного из них
поиск по именам не находил: их имена не содержат фразы «test impact».

**Как сочетать два подхода.** Поиск по описанию находит проекты, о существовании которых не
знаешь; проверка по именам (`check_predecessors.py`) ловит то, чего нет на GitHub — прежде всего
PyPI-пакеты. Порядок работы: сначала каталог по фразе, затем прогон найденных имён через
`check_predecessors.py` и `verify.py` для adoption и живости.

## Шаг 6. Итог: что делать дальше

Каталог (или срез каталога) → список имён → `check_predecessors.py` → план. Обратный порядок
(придумать имя и проверить его) работает хуже: имена не содержат слов задачи, и половина
предшественников остаётся невидимой.

## Не только про MCP

Ни один из скриптов не содержит логики «MCP» как таковой. MCP — это лишь значение по умолчанию
для одной переменной (`KEYWORD` в verify.py, `PRED_KEYWORDS` в check_predecessors.py).

### Что работает вообще без признака

Существование пакета, версия и дата релиза, adoption, вердикт живости/застоя, аудит манифеста,
сравнение прогонов во времени, свобода имени, похожие имена, CSV и гейт по коду выхода — это
анализ здоровья пакетов и репозиториев. К MCP он отношения не имеет и без него полезен.

### Как задать другой вопрос

```bash
# что декларируют пакеты (сканирование метаданных и описания)
python check_predecessors.py --keyword deprecated nose pytest
python check_predecessors.py --keyword otel --keyword opentelemetry fastapi sqlalchemy pandas

# какой артефакт класса X есть у инструмента (поиск по репозиториям)
python verify.py --keyword "helm chart" prometheus/prometheus
python verify.py --keyword "vscode extension" astral-sh/ruff
```

Результаты последних прогонов: Helm-чарты есть у traefik (официальный, 1419★) и prometheus
(6218★); OpenTelemetry в своих метаданных не декларирует ни один из четырёх (fastapi,
sqlalchemy, pandas, numpy); статус `ЗАСТОЙ` впервые сработал на nose — 6 млн скачиваний в месяц
при релизе 2015 года.

### Каталог и плотность — тоже не про MCP

`collect.py`, `coverage.py` и `catalog_scan.py` — это общий каркас работы с любым реестром
с пагинацией: npm, PyPI, VS Code Marketplace, Homebrew, расширения JetBrains. Правишь URL
каталога, ключ курсора и список классов в `CLASSES` — и получаешь карту плотности для своей
экосистемы.

### Сводка: какие вопросы закрывает один и тот же код

| Вопрос | Чем |
|---|---|
| Эта ниша/имя заняты? | `check_predecessors.py`, `verify.py` |
| Эта зависимость жива? | вердикты + колонка даты (состояние `ЗАСТОЙ`) |
| Какой из трёх аналогов выбрать? | тот же прогон на трёх именах, сравни adoption и даты |
| Свободно ли имя для нового продукта? | `--check-name` |
| Что изменилось у конкурентов за месяц? | `--diff` по накопленному JSON |
| Не подсунут ли пакет-двойник? | `--similar` |
| Этот список пакетов не выдуман? | прогон имён через таблицу |
| У скольких инструментов есть артефакт класса X? | `verify.py --keyword` |
| Где пусто и где перегрето в экосистеме? | `catalog_scan.py` + `coverage.py` |

### Ограничение keyword-режима

Сканируются имя, описание и метаданные — то есть только то, что автор заявил сам. Отсутствие
признака не равно отсутствию функциональности: пакет может поддерживать OpenTelemetry, не
упомянув этого в summary. Поэтому отсутствие признака — повод копать глубже, а не вывод.

## Матрица решений: adoption × MCP-поверхность

Все четыре клетки означают разное, и путать их дорого:

| adoption | MCP | Что делать |
|---|---|---|
| высокий | нет | **Лучший вход.** Пользователи есть, агентского интерфейса нет. Пример: ruff, uv, mypy, alembic, sqlalchemy — от 113 до 330 млн скачиваний в месяц, MCP нет ни у одного |
| высокий | есть | не лезть: вендор уже там (polars в той же выборке) |
| низкий | нет | рынок не сформирован: либо задача не болит, либо всё делают руками. Вход только с гипотезой «почему не болит» |
| низкий | есть | «опробовано и не взлетело» (ci-triage: 0 скач/нед, MCP есть). Вход возможен, но выигрыш только в качестве и adoption |

## Сценарии

**Выбрать нишу для нового продукта.** Сначала `check_predecessors.py` по 10–15 именам
кандидатов из своей области, затем `verify.py` по инструментам с большим adoption и MCP=нет.
Фраза-победитель: пакет живой, adoption в миллионах, MCP нет — значит есть аудитория и нет
интерфейса.

**Проверить имя перед публикацией.** `--check-name`. Дешевле сменить бренд сейчас, чем после
релиза: занятое имя в PyPI/npm не отдают никогда.

**Аудит зависимостей проекта.** `--from requirements.txt --csv deps.csv`. Ищутся пакеты
с вердиктом `МЁРТВО`, то есть реально тянущиеся годами зависимости без развития.

**Мониторинг конкурентов по расписанию.** Раз в месяц тот же `--from` с `--diff` на
предыдущий JSON. Событие `MCP ПОЯВИЛСЯ` — самый ценный сигнал: вендор закрыл нишу, и решение
об интеграции надо пересматривать. Флаг `--strict` даёт код выхода 2, которым можно
остановить пайплайн.

**Типосквоттинг и supply chain.** `--similar install-required-name` перед командой установки.
Расстояние 1–2 до популярного имени при том, что точное имя существует с недавней датой
публикации — признак подмены.

**Проверка списка имён на выдуманность.** Любой список пакетов от модели (в том числе от
себя) прогоняй через `check_predecessors.py`: имена, которых нет ни в PyPI, ни в npm,
в заметной части случаев просто сгенерированы. Так были отловлены три несуществующих
пакета в разборе чужого плана.

## Где живут данные и что делать с результатами

Скрипты пишут в `raw/` относительно текущей папки: `catalog.json`, `popular.json`,
`gap_analysis.json`, `predecessors.json`, `verify.json`, кэш `.pcache.json`.

Помни два свойства окружения:
- `TMPDIR` чистится примерно через сутки — рабочие данные и итоговый отчёт копируй в свою папку;
- кэш (12 часов) делает повторные прогоны мгновенными, но и «держит» устаревшие факты.
  Если нужны свежие цифры по конкретному пакету — удали `.pcache.json`.

## Cron и CI

```bash
# месячный отчёт с обнаружением изменений; deliver на Telegram — из CLI уведомления не приходят
python check_predecessors.py --from requirements.txt --diff raw/predecessors.json --csv report.csv
```

Для гейта в пайплайне ставь `--strict`: код возврата `2` означает «есть живой конкурент или
вендор уже встроил MCP». Ненулевой код удобно ловить в CI, нулевой (свободное имя,
отсутствие конкурентов) — сигнал двигаться дальше.

## Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| Каталог собрался за секунду, записей подозрительно мало | Неверный ключ курсора или предохранитель по страницам. Проверь в ответе имя ключа (`nextCursor` против `next_cursor`) и убери лимит страниц |
| Обход падает на середине с 5xx | Публичный реестр отдаёт 500 на глубине (каждые ~40 страниц). Нужны повторы с backoff и чекпоинт каждые 25 страниц — готовый шаблон `scripts/catalog_scan.py` |
| `search` в реестре даёт 0–1 на всё | Параметр матчит не по описаниям. Плотность считай самостоятельно обходом каталога, а не через `search` |
| Пустые/шумные результаты от `gh` | Лимит Search API — 30 запросов/мин. Ставь `sleep 2.5`; проверь `gh auth status` |
| Скачивания `None` | PyPI-статистика отдаёт 429 или пакета нет в этом реестре. Скрипт сам идёт в npm; если и там пусто — оставь пусто, не подставляй ноль |
| Вердикт «ЗАГЛУШКА» на популярный инструмент | Прочитай напечатанную находку: на коротких именах поиск даёт чужой проект |

## Ограничения, о которых надо сказать вслух

- Сопоставление «есть ли решение» идёт по именам и описаниям — это прокси. Возможны и
  пропуски, и ложные срабатывания; ключевые выводы добивай точечными проверками.
- «MCP: нет» у пакета не означает отсутствие сторонних серверов. Полная картина — только
  в связке с `verify.py` и проверкой дерева файлов продукта.
- Звёзды и скачивания — не истина. Годятся как грубый сигнал «мёртвое против живого».
- Любая дата замера быстро устаревает: вендор может выпустить сервер за день. Перед началом
  работы по любой нише прогоняй проверку заново, а не ссылайся на прошлый отчёт.
