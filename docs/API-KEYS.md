# API-ключи для GapAudit

## Зачем

GapAudit работает без ключей: базовая матрица, вердикты, каталоги, мониторинг,
momentum, cross-ecosystem. Ключи нужны только для сигналов ниш: спрос на труд
(jobs), патенты (patents), финансирование (funding), поисковый интерес
(search_interest). Без ключа сигнал показывает «не настроен», остальное
приложение работает.

## Где вводить

В приложении: **Настройки → API-ключи**. Для каждого провайдера — поле ввода,
кнопки «Сохранить», «Проверить», «Удалить». Статус: «не настроен» / «настроен» /
«проверка пройдена» / «ошибка».

Ключи хранятся в `<data_dir>/api_keys.json` (права 0600), **не в базе данных** —
при экспорте или копировании БД ключи не утекают. Шифрование — base64, защита —
права файла, не криптография. Не публикуйте этот файл.

Файл `api_keys.json` лежит рядом с базой данных:

- dev-режим (запуск из клона): `data/api_keys.json`;
- обычный режим: `%USERPROFILE%\GapAudit-data\api_keys.json`.

<a id="adzuna"></a>
## Adzuna (jobs — спрос на труд по странам)

**Что даёт:** количество вакансий по ключевому слову в 11 странах (UK, US, DE,
FR, NL, AU, BR, IN, IT, ES, CA). Прямой сигнал спроса: «в Германии 200
вакансий с Rust, в Италии — 12».

**Что нужно:** `app_id` + `app_key`.

**Как получить:**

1. Открыть https://developer.adzuna.com/
2. Нажать «Sign up» (бесплатно).
3. Заполнить форму (имя, email, организация, тип применения — «Personal or
   academic research» для нашего случая) и подтвердить email.
4. В личном кабинете → «API Access» → скопировать `app_id` и `app_key`.

**Как вызывать:**

```
https://api.adzuna.com/v1/api/jobs/{country}/search/1
  ?app_id={APP_ID}&app_key={APP_KEY}
  &what={ключевое_слово}&results_per_page=1&content-type=application/json
```

`{country}` — двузначный код: `gb`, `us`, `de`, `fr`, `nl`, `au`, `br`, `in`,
`it`, `es`, `ca`.

**Лимиты (free tier, ToS Adzuna):** 25 hits/мин, 250 hits/сутки, 1000 hits/нед,
2500 hits/мес. Один запрос = одна страна + одно ключевое слово; 5 стран на один
пакет = 5 запросов. Планируйте и кэшируйте ответы.

**Важно про ToS:** Adzuna прямо запрещает использовать счётчики вакансий в
агрегированном виде для постоянных исследований без письменного согласия. Для
«Personal or academic research» обязательна атрибуция «The Adzuna API» со
ссылкой на adzuna.co.uk. В GapAudit атрибуция показывается рядом с сигналом;
если планируется коммерческое или командное использование — сначала письменное
согласие Adzuna, иначе сигнал `jobs` лучше не включать.

**Без ключа:** сигнал «не настроен».

<a id="patentsview"></a>
## PatentsView (patents — патентный импульс)

**Что даёт:** количество патентных заявок по ключевому слову / CPC-классу за
год в сравнении с прошлыми годами. «Патентный импульс +40%» = крупные игроки
вкладываются в IP.

**Что нужно:** `api_key` (бесплатно, по заявке).

**Как получить:**

1. Открыть https://patentsview.org/apis/key-request
2. Заполнить форму (имя, email, организация).
3. Подтвердить email.
4. Скопировать `api_key` из письма.

**Как вызывать:**

```
https://search.patentsview.org/api/v1/patent/?q={запрос}&api_key={API_KEY}
```

**Лимиты:** 45 запросов/мин, без оплаты (уточнить при подключении — значения
менялись).

**Замечание об именах:** API — `search.patentsview.org` (PatentsView, NIH/NSF).
Не путать с `api.uspto.gov` — это другой API, отдельный провайдер, в текущей
версии не подключён.

**Без ключа:** сигнал «не настроен».

<a id="sec-edgar"></a>
## SEC EDGAR (funding — раунды финансирования)

**Что даёт:** официальные уведомления о привлечении капитала (США). Form D
выходит ДО пресс-релизов. «В нише 3 раунда за квартал» = горячо, вход дорогой.

**Что нужно:** НЕ ключ, а User-Agent с email. SEC требует идентификации:
`"GapAudit your-email@example.com"`. Без него — 403.

**Как настроить:**

1. Открыть https://www.sec.gov/os/accessing-edgar-data
2. Прочитать требование: «Please declare your user agent in the request header».
3. В поле «User-Agent» ввести: `GapAudit your-email@example.com`.
4. Сохранить. В GapAudit это попадает в `providers.edgar.meta.user_agent`.

**Как вызывать:**

```
https://efts.sec.gov/LATEST/search-index?q={запрос}&forms=D
```

(Form D — уведомление о предложении, там есть сумма.)

**Лимиты:** 10 запросов/сек.

**Без User-Agent:** сигнал «не настроен» (403 от EDGAR).

<a id="yandex-wordstat"></a>
## Yandex Wordstat (search_interest — поисковый интерес, РФ)

**Что даёт:** частотность запросов, динамика интереса, срезы по регионам и
устройствам. Идеален для РФ: «в Москве интерес растёт, в регионах —
стагнирует».

**Что нужно:** OAuth-токен + ClientId + заявка на доступ.

**Как получить:**

1. Авторизоваться с Яндекс ID.
2. Создать приложение на https://oauth.yandex.com/client/new/id
   (приложение типа «ID»), получить OAuth-токен.
3. На странице приложения найти `ClientId`.
4. Подать заявку на доступ к API Вордстата через поддержку Яндекс Директа
   (указав логин и `ClientId`).
5. В GapAudit: `encrypted_value` = OAuth-токен, `meta.client_id` = `ClientId`.

**Запрос:** POST `api.wordstat.yandex.net/v1/topRequests`. Параметры:
`{"phrase": query, "regions": [225], "devices": ["all"]}`. ВАЖНО: `regions` —
список ЧИСЕЛ (225 = Россия), не строка. `client_id` в запросе НЕ передаётся —
он привязан к токену при регистрации приложения. Если клиент передал
`client_id` в запросе — Яндекс вернёт 401. `/v1/topRequests` — срез за 30 дней,
`trend_pct = None`. Ряд за 12 месяцев — `/v1/dynamics` (другая форма ответа,
follow-up).

**Как вызывать:**

```
POST https://api.wordstat.yandex.net/v1/topRequests
Authorization: Bearer <OAuth-токен>
```

(Полезно знать: функциональность Вордстата также доступна через Yandex Search
API в Yandex Cloud — если старый endpoint перестанет отвечать, миграция
туда — следующий шаг.)

**Лимиты:** квота на запросы в секунду и в сутки. При превышении —
`429 Quota limit exceeded, try again later. Time to refill: N seconds`; это
время надо выждать. В сети встречаются значения 10 запросов/сек и 1000
запросов/сутки — проверьте свои при выдаче доступа.

**Без ключа:** сигнал «не настроен».

<a id="google-trends"></a>
## Google Trends (search_interest — глобальный поисковый интерес)

**Что даёт:** индекс поискового интереса, динамика, разбивка по странам и
регионам.

**Варианты (пользователь выбирает сам):**

### Вариант A: официальный Google Trends API (alpha)

- **Доступ:** по заявке, ограниченный круг разработчиков.
- **Стоимость:** бесплатно.
- **Как получить:** подать заявку на early access на
  https://developers.google.com/search/apis/trends (описание API и форма
  заявки в одном месте; анонс — блог Search Central от 24.07.2025:
  https://developers.google.com/search/blog/2025/07/trends-api).
- **Что даёт:** 5 лет данных, агрегация day/week/month/year, регионы и
  субрегионы, consistently scaled volume.
- **Ограничения:** alpha, не для production; функциональность может меняться.
  Данные не нормированы 0–100, как в веб-интерфейсе Trends, — это абсолютный
  объём интереса.

<a id="apify"></a>
### Вариант B: Apify (Google Trends Scraper)

- **Доступ:** сразу, по API-токену Apify.
- **Стоимость:** pay-per-result; порядок цены — около $1.20 за 1000
  результатов, точная цена — на странице актора (она меняется).
- **Как получить:**
  1. Зарегистрироваться на https://apify.com/ (есть бесплатный tier).
  2. Взять API-токен в личном кабинете.
  3. Найти актора «Google Trends Scraper» в Apify Store, скопировать
     `actor_id` (вид `owner/actor-name`).
- **Что нужно ввести в GapAudit:** `api_key` (Apify token) + `meta.actor_id`.

### Вариант C: DataForSEO

- **Доступ:** сразу, по логину и паролю (или API-ключу).
- **Стоимость:** pay-per-task; минимальное пополнение — порядка $50, дальше
  оплата за задачи.
- **Как получить:** регистрация на https://dataforseo.com/.
- **Что нужно ввести:** логин + пароль.

**Без ключа:** сигнал «не настроен».

## GitHub (уже есть)

`gh auth status` — авторизованный `gh` даёт 5000 запросов/час вместо 60. Не
требует ввода ключа в приложении: используется системный `gh`.

## Что будет без ключей

Работает всё, кроме signals:

- Матрица «Сейчас решать» (adoption × признак) — работает.
- Вердикты (ЖИВО/МЁРТВО/ЗАСТОЙ) — работают.
- Каталоги (сборка по фразам) — работают.
- Мониторинг (timeline событий) — работает.
- Momentum (Δ adoption) — работает (данные из observations).
- Cross-ecosystem — работает (данные из observations).
- Gap Score — считается частично (adoption + momentum + признак); приложение
  честно показывает, сколько компонент учтено.

Не работают без ключей:

- Jobs (Adzuna) — «не настроен».
- Patents (PatentsView) — «не настроен».
- Funding (SEC EDGAR) — «не настроен».
- Search interest (Yandex Wordstat / Google Trends) — «не настроен».

## Проверка ключа

В UI «Настройки → API-ключи» → кнопка «Проверить» делает минимальный тестовый
запрос:

- Adzuna: `GET /v1/api/jobs/gb/search/1?app_id=…&app_key=…&what=test&results_per_page=1`
- PatentsView: `GET /api/v1/patent/?q=test&api_key=…` (уточнить форму при
  подключении)
- EDGAR: `GET /cgi-bin/browse-edgar?action=getcompany&company=test&type=8-K`
  с заголовком User-Agent из `meta.user_agent`
- Yandex Wordstat: `POST /v1/topRequests` с `phrase=test` и Bearer-токеном
- Google Trends (Apify): запуск актора с минимальным input

Успех = 200 + непустой результат. Ошибка = сообщение от API (в UI — текст
ошибки, ключ при этом не показывается).

## Безопасность

- Файл `<data_dir>/api_keys.json` — права 0600 (POSIX) / icacls (Windows).
- Не логировать значения ключей.
- Не публиковать файл (в .gitignore).
- Шифрование — base64 (P4), опционально Fernet (P5).
- В API отдаётся только статус провайдера, не значение.
- В базе данных ключей нет, поэтому экспорт/копирование БД их не утекает.
